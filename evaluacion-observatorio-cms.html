🔄 4. Comparativo: Portal viejo vs nuevo

Portal Viejo (legacy)

  • PHP plano sin framework ni CMS
  • Cada observatorio = archivo PHP independiente (indic-economico.php, indic-social.php, etc.)
  • CSS/JS específico por dimensión (5 archivos diferentes)
  • Tableros embebidos de Power BI directamente
  • 385 indicadores con datos reales en archivos .csv + .info
  • Admin rudimentario: solo upload de archivos CSV por número
  • Sin sistema de usuarios, roles ni permisos
  • Sin workflow de publicación
  • Sin auditoría de cambios
  • Sin API pública
  • Sin contadores ni encuestas
  • Contenido de género rico (barreras, rutas, mapas)
  • HTML con errores (h2 cerrado como h12 en género)

Portal Nuevo (CMS unificado)

  • Arquitectura CMS con BD relacional completa
  • 1 template unificado (observatorio.php?slug=X) para todos
  • CSS unificado con variables por observatorio
  • Tableros propios con Google Charts + opción embeber
  • Estructura de BD lista pero 0 datos migrados
  • Panel CMS completo: banners, noticias, tableros, gráficos, redes, RAG
  • Usuarios con roles, permisos granulares por módulo
  • Workflow draft→published con tabla de auditoría
  • Audit logs completos
  • API REST con CORS
  • Contadores únicos + encuesta de satisfacción
  • Migró contenido de género (barreras) al nuevo template
  • HTML limpio, semántico, accesible

✅ 6. Veredicto: ¿Es un observatorio real?

Un observatorio territorial funcional debe cumplir con producción de datos, análisis, difusión y gestión. Evaluación por eje:

Eje de observatorioCumpleNota
Recolección y sistematización de datos Parcial La infraestructura (BD, API, CMS) está lista para recibir datos. Pero actualmente tiene 0 registros en el nuevo sistema. Los 385 indicadores con datos CSV existen solo en el sistema viejo de archivos planos.
Análisis y generación de conocimiento Parcial El sistema de tableros y gráficos existe, las hojas de vida están diseñadas, y hay RAG para IA. Pero sin datos cargados no se genera análisis real.
Difusión y transparencia Cumple Portal público accesible, API JSON abierta, descarga de datos planificada, contadores de visitas, redes sociales integradas, encuesta ciudadana.
Gestión institucional Cumple CMS con roles, permisos, auditoría, workflow de publicación. Separación editorial por observatorio. Gobernanza de datos implementada.
Continuidad y sostenibilidad Parcial El código es mantenible y modular. Pero depende de migración de datos y adopción del CMS por el equipo. Sin datos, el observatorio es una cáscara.

💡 7. Recomendaciones prioritarias

1. CRÍTICO: Migrar los 385 indicadores del sistema viejo al CMS Los archivos indicador/XXXX/indicador.info y *.csv contienen datos reales que deben ingestarse en las tablas indicators e indicator_observations. Sin esto, el observatorio nuevo no tiene razón de ser. Se puede automatizar con un script PHP/Python.
2. CRÍTICO: Ejecutar migraciones y seeds de la BD Las migraciones 007 (dashboards por defecto) y 008 (gráficos demo) necesitan ejecutarse. También run_content_seed.php. El portal muestra mensajes de "ejecute la migración" al público.
3. ALTA: Cargar contenido mínimo viable Al menos 1 banner, datos de contacto, 3-5 noticias por observatorio, y 1 tablero con gráficos por dimensión. Un observatorio vacío transmite abandono.
4. ALTA: Resolver la coexistencia viejo/nuevo El portal nuevo tiene enlaces "Vista actual" que apuntan al viejo. Si el nuevo reemplaza al viejo, los 385 indicadores deben migrar. Si coexisten, definir claramente qué vive dónde.
5. MEDIA: Integrar o reemplazar Power BI El viejo embebe tableros Power BI. El nuevo tiene su sistema de gráficos Google Charts. Definir si se migra a Charts o se mantiene Power BI embebido. Ambos caminos son válidos pero no dejar los tableros vacíos.
6. MEDIA: Testing de responsividad y accesibilidad Probar en dispositivos reales. El HTML es semántico y usa ARIA labels, pero falta validación real en lectores de pantalla y móviles.

🎯 Resumen ejecutivo

El portal nuevo tiene una arquitectura de observatorio profesional y un CMS sólido. La estructura de base de datos, el sistema de roles, el workflow de publicación, la API, los contadores y la integración con IA/RAG son superiores a la mayoría de observatorios territoriales en Colombia.

El problema principal es que está vacío. Los 385 indicadores con datos reales que dan vida al observatorio viven solo en el sistema viejo de archivos planos. Hasta que esos datos no se migren y se cargue contenido editorial mínimo, el observatorio nuevo es una estructura sin contenido — como un edificio terminado pero sin muebles.

Puntuación: 68/100 — Infraestructura excelente (90/100), contenido cargado insuficiente (20/100). Con la migración de datos y carga de contenido mínimo, podría subir a 85-90 fácilmente.
